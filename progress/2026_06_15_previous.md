## 구현된 API

| 메서드 | 경로 | 설명 | 상태 |
|---|---|---|---|
| POST | `/api/v1/auth/signup` | 회원가입 | ✅ 완료 |
| POST | `/api/v1/auth/login` | 로그인 (Access Token body + Refresh Token 쿠키) | ✅ 완료 |
| POST | `/api/v1/auth/refresh` | Access Token 재발급 | ⏳ 미구현 (Step 6) |
| POST | `/api/v1/auth/logout` | 로그아웃 | ⏳ 미구현 (Step 6) |

## 아직 구현 안 된 것

### Step 5 — JWT 필터 + Security 완성
- `JwtFilter.java` — 요청마다 Access Token 검증 후 SecurityContext에 인증 정보 주입
- `SecurityConfig.java` — JwtFilter를 FilterChain에 등록

현재 `/signup`, `/login` 외 모든 API가 401을 반환하지만, JWT 필터가 없어서 토큰을 줘도 인증이 안 됨

### Step 6 — 토큰 재발급 + 로그아웃
- `POST /api/v1/auth/refresh` — Refresh Token 쿠키로 Access Token 재발급
- `POST /api/v1/auth/logout` — Refresh Token 무효화 (revoked_at 업데이트) + 쿠키 만료

## 주요 설계 결정사항 (빠른 참고용)

| 항목 | 결정 |
|---|---|
| 토큰 저장 | Access Token → body, Refresh Token → HttpOnly Cookie |
| Refresh Token DB 저장 | 원문 대신 SHA-256 해시 저장 |
| 동시성 전략 | 낙관적 락 (`auctions.version`) 으로 시작, 부하 테스트 후 재검토 |
| 소프트 삭제 | `@SQLRestriction("deleted_at IS NULL")` 적용 |
| DTO 구조 | auth/user/bid → 파일 하나 통합, auction → 기능별 분리 |
| 에러코드 | 도메인별 Enum 분리 (AuthErrorCode, UserErrorCode 등) |
| BaseEntity 분리 | 도메인 엔티티 → BaseEntity, 로그형 → BaseLogEntity |
